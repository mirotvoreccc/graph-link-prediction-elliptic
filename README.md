# Восстановление скрытых рёбер графа Elliptic

Воспроизводимый эксперимент по курсовой работе: для каждого временного среза графа Bitcoin-транзакций часть известных рёбер скрывается. По **наблюдаемой** части графа модель оценивает, какие пары узлов были связаны. Затем проверяется, переносится ли модель на более поздние срезы.

Это **восстановление рёбер внутри среза**, а не прогноз будущих платежей или классификация незаконных транзакций. В опубликованном наборе Elliptic нет рёбер между временными срезами. Эксперимент не использует метки `licit/illicit` и 165 признаков узлов.

## Данные

Источник: [Elliptic Data Set от Elliptic](https://www.kaggle.com/datasets/ellipticco/elliptic-data-set). Датасет содержит 203 769 узлов, 234 355 направленных рёбер и 49 временных шагов. В этом эксперименте направление рёбер не учитывается: каждое ребро рассматривается как связь между двумя транзакциями. **Данные не входят в репозиторий.** На странице источника указана лицензия CC BY-NC-ND 4.0; перед другим использованием проверьте её условия.

Скачайте исходный датасет с Kaggle и положите два файла в папку `data/`:

```text
data/
├── elliptic_txs_features.csv
└── elliptic_txs_edgelist.csv
```

Файл `elliptic_txs_classes.csv` для этой задачи не нужен. Для построения временных срезов из `elliptic_txs_features.csv` читаются только ID транзакции и номер шага.

## Запуск

Рекомендуется Python 3.11–3.13.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python src/experiment.py --data-dir data --output results.json
python -m unittest discover -s tests -v
```

Скрипт проверяет, что концы каждого ребра находятся в одном временном срезе. Случайность фиксируется параметром `--seed` (по умолчанию 42), доля скрытых рёбер — `--holdout` (по умолчанию 0,2).

## Методика

1. Для каждого из 49 срезов случайно скрываем 20% существующих рёбер. **Все признаки** считаются только по оставшемуся графу.
2. Формируем столько же отрицательных пар случайным выбором узлов. Каждую пару проверяем по **полному** графу среза, чтобы скрытое ребро не попало в отрицательный класс.
3. Для пары считаем число общих соседей, коэффициент Жаккара, Adamic–Adar и произведение степеней.
4. Шаги 1–34 идут в обучение, 35–40 — в валидацию, 41–49 — в тест. Выбираем между логистической регрессией и Random Forest по Average Precision на валидации. Тест используется один раз после выбора.

Разделение по шагам проверяет переносимость на более поздние независимые графы. Внутри каждого шага скрытые рёбра используются как примеры положительного класса; модель не видит их при вычислении признаков.

## Проверенный результат

Запуск с `seed=42`, `holdout=0.2` на всех 49 срезах:

| Модель | Validation ROC-AUC | Validation AP |
| --- | ---: | ---: |
| Logistic Regression | 0,4095 | 0,5799 |
| Random Forest | **0,7897** | **0,7564** |

После выбора Random Forest: **Test ROC-AUC 0,7741**, **Test AP 0,7446** на 19 300 тестовых парах. Полные параметры и числа сохранены в [results.json](results.json).

Отрицательные пары выбраны в равном количестве с положительными. Поэтому эти метрики характеризуют данный контролируемый эксперимент, а вероятности модели **не калиброваны** к реальной доле рёбер среди всех возможных пар.

## Ограничения и связь с курсовой

Исходная курсовая также рассматривала GNN и эмбеддинги узлов. В её ноутбуке использовались разные схемы разделения рёбер, а часть итоговых чисел и графиков задавалась вручную. Эти результаты здесь не воспроизводятся и не заявляются как проверенные. Этот репозиторий содержит самостоятельную, более узкую контрольную постановку с исполняемым кодом и повторно измеренными метриками.

Дальнейшее развитие: добавить сравнение с GCN/GAT при таком же корректном разделении, провести несколько запусков с разными `seed` и проверить влияние способа выбора отрицательных пар.
